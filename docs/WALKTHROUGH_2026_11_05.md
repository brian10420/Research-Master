# New-user walkthrough and documentation review — research-master 0.7.1

Date: 2026-11-05 · branch `cloud/new-user-walkthrough-2026-11-05` · base `a426fdb` (main, 0.7.1)

Setup: a clean Linux container (Ubuntu-like) with Claude Code 2.1.318 on `PATH`. The plugin
was installed into a scratch `HOME`. I used the CLI equivalents of the slash commands
(`claude plugin marketplace add …`, `claude plugin install …`). A fresh `git init` project
was seeded by following `templates/project-state/README.md` and README step 3. Skill
loading was tested headless (`claude -p`). Interactive `/reload-plugins` and interactive
skill invocation were **not** tested, because nobody was at the terminal.

What worked as documented:
- `marketplace add brian10420/research-master` and `plugin install research-master@research-master` succeed.
- `claude plugin details research-master` shows 0.7.1, 9 skills and 5 agents, as README line 202 says.
- `python3 tools/check_drift.py` reports `OK — 66 adapters`, matching the "66 files" in the compile-layer block.
- `claude plugin validate .` passes, with one warning (see M-5).
- Versions agree: `.claude-plugin/plugin.json` 0.7.1 = `marketplace.json` 0.7.1 = top `CHANGELOG.md` entry 0.7.1.
- Every relative link and `<img src>` in `README.md`, `README.zh-TW.md`, `CHANGELOG.md` and `assets/README.md` resolves to a file that exists.
- I extracted the text of every figure. The README captions (day-one, team-map, role-bears, team-flows with six lanes, plan-tier, scenarios 1–9) match the text drawn in the SVGs.

## Findings

### Blocker

**B-1 · Skills fail to load in headless mode.** Files: `skills/*/SKILL.md:4` and `:29`,
generated by `tools/sync.py:367` and `:387`. This is code, so I did not change it.
- Running `claude -p "/research-master:research-mentor …"` in a seeded project stopped with `Shell command permission check failed`. No ACK line came back. It failed twice:
  1. The `!cat ${CLAUDE_SKILL_DIR}/RULES.md` injection was blocked, because the plugin cache is outside the session's allowed working directories ("may only concatenate files from the allowed working directories").
  2. With `--add-dir ~/.claude/plugins` (and also with `--allowedTools "Bash(cat:*)"`), the overlay injection `cat ${CLAUDE_PROJECT_DIR:-.}/… 2>/dev/null || echo …` still failed: "A variable in braces in this command can't be checked before it runs".
- The `allowed-tools` pattern on line 4 (`cat ${CLAUDE_PROJECT_DIR}/…`) does not match the command on line 29 (`${CLAUDE_PROJECT_DIR:-.}`, plus `2>/dev/null || echo`).
- The wrapper's fallback ("If a section above did not load … read `role.md` … with the Read tool") never runs, because the whole skill invocation is refused before the model sees it.
- Interactive mode may show a permission prompt instead. I could not test that here.
- Severity is blocker for headless/scripted use. It is at least major for interactive use, where it may cost a first-time user a confusing prompt or a failure on README step 4.

### Major

**M-1 · Steps 2–3 assume a local clone that the plugin route never creates.** Files: `README.md:31–37`, `README.zh-TW.md:26–27`, `templates/project-state/README.md:14`.
- The commands copy from `<research-os>/templates/…`. A user who only ran `/plugin install` has no such directory and is never told where the templates are.
- Observed on 2.1.318: the templates are in `~/.claude/plugins/marketplaces/research-master/templates/` and `~/.claude/plugins/cache/research-master/research-master/0.7.1/templates/`.
- The placeholder `<research-os>` is not defined anywhere a new user would look.
- *Fixed in docs (E-3, E-4, E-6).*

**M-2 · The day-one figure shows the undefined `<research-os>` placeholder.** File: `assets/day-one.svg`, the step-2 card ("cp <research-os>/templates/ …").
- Same issue as M-1, but in a figure. The figure is covered by a claims table, so I did not change it.
- The README text now explains the placeholder, but the figure still does not.

**M-3 · Scenario 3: `tools/anonymize.py` is a repository-relative path.** Files: `README.md:114`, `README.zh-TW.md:80`.
- A plugin user's project has no `tools/`.
- The script seals label maps in `ROOT/eval/.sealed/`, where `ROOT` is the script's own repository (`tools/anonymize.py:33–34`). For a plugin user that is inside the plugin cache, which an update replaces wholesale. So the sealed map is not protected by any `.gitignore` the user controls, and it may be lost.
- Neither README says where to run the tool from or where its output goes.
- I did not change this: it touches code and design, and needs a decision.

**M-4 · Scenarios 7 and 8 depend on tools that are not named or linked.** Files: `README.md:139–150`, `README.zh-TW.md:96–102`.
- Scenario 7 needs a "docx skill" with `scripts/office/validate.py` and `soffice.py`, plus LibreOffice and `pdftoppm` (poppler). Its figure says `/desktop` works only "on macOS and x64 Windows". An Ubuntu user cannot take the desktop branch, and the README does not say so.
- Scenario 8 names superpowers and "ARS" (academic-research-skills 3.23.1, according to `assets/README.md:1000`). Neither README links ARS or says how to install it.
- Both scenarios are marked *Operator's setup*, which helps. Still, a new user cannot reproduce them from the docs.
- I did not change this: adding install sources would mean adding content the operator has not decided on.

**M-5 · "Using it without the plugin", step 2, copies `CLAUDE.md` into the project.** File: `README.md:353`.
- This overwrites any existing project `CLAUDE.md`. The copied file also points to `core/…` paths that do not exist in the project.
- `claude plugin validate .` warns: "CLAUDE.md at the plugin root is not loaded as project context."
- The README does not warn about either. Left unchanged, because the copy step is a design choice to confirm.

### Minor

- `github.com/obra/superpowers` does contain `skills/writing-skills/SKILL.md`, which is the skill the README credits.
- *Link fixed (E-5).* The wording "Anthropic superpowers plugin" is unchanged; see N-4.

**m-2 · Stale decision range in the layout block.** Files: `README.md:224`, `README.zh-TW.md:161`. The block said `DECISION_000 … DECISION_008`, but `core/DECISIONS.md` runs to DECISION_012. *Fixed (E-1).*

**m-3 · Incomplete `assets/` entry in the layout block.** Files: `README.md:235`, `README.zh-TW.md:172`. It listed only the logo, team map, workflows, day-one and plan-tier figures, leaving out `role-bears.svg`, `roles/` and `scenarios/`. *Fixed (E-2).*

**m-4 · Missing `mkdir -p .claude`.** Files: `README.md:40`, `README.zh-TW.md:27`, `templates/project-state/README.md:24`. In a fresh repository, `cp … .claude/research-master.overlay.md` fails because the directory does not exist. *Fixed (E-3, E-4, E-6).*

**m-5 · Brace expansion breaks in `sh`.** File: `templates/project-state/README.md:14`. The `{A,B,…}.md` list is bash-only. Under `sh`/`dash`, Ubuntu's `/bin/sh`, it fails with `cannot stat '…/{RESEARCH_STATE,DECISIONS}.md'`. The fence is labelled `bash`, but the README never states the shell. *Note added (E-6).*

**m-6 · Missing pilot file cited as a source.** File: `assets/README.md:507` and `:941`. Both cite `05-claims.md` ("as in the pilot"), which is not in the tree or in git history. Line 941 is inside a claims table, so I did not edit it.

**m-7 · Prerequisites not stated.**
- No minimum Claude Code version is given; the plugin and the `/reload-plugins` command need a recent one.
- No OS is stated; scenario 7's `/desktop` excludes Linux.
- `python3` is required for the tools.
- `git` is required, and the marketplace add needs network access to GitHub.
